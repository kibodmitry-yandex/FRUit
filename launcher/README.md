# FRUit — exe-лаунчер (тонкий)

`FRUit.exe` — **тонкая** запускашка (как `MyBL.exe` у модуля mybl): она НЕ
содержит кода утилиты. При каждом запуске она берёт **текущий** пакет `fruit`
и запускает его питоном окружения. Поэтому после правок `.py` и перезапуска
исполняется свежий код, а не «запечённая» копия — пересобирать exe нужно только
если меняется сам лаунчер или иконка.

## Как получить exe

```bat
launcher\build_launcher.bat
```

Компилирует `launcher\FruitLauncher.cs` системным компилятором C#
(.NET Framework, `csc.exe`) в `FRUit.exe` — **без окна консоли**
(`/target:winexe`). Никаких зависимостей/PyInstaller не нужно.

## Что делает

1. Находит каталог, где лежит пакет `fruit` (`fruit\__main__.py`):
   - `%FRUIT_HOME%`, если задан;
   - иначе поднимается от места exe (лаунчер обычно в корне FRUit);
   - иначе `F:\FRUit`.
2. Находит питон:
   - `%FRUIT_PYTHON%`, если задан;
   - иначе `.venv\Scripts\pythonw.exe` (для трея) / `python.exe` (для CLI);
   - иначе `python.exe` из PATH.
3. Выбирает режим:
   - **без аргументов** (или `tray`) — тихий трей: запускает
     `pythonw -u -X utf8 -m fruit tray`, весь вывод → `logs\fruit.log`,
     и лаунчер сразу завершается (в памяти не висит);
   - **с аргументами** (`list`, `restore work`, …) — выделяет консоль
     (`AllocConsole`) и запускает `python -u -X utf8 -m fruit <аргументы>`,
     ждёт завершения — вывод остаётся в окне.

Аргументы пробрасываются: `FRUit.exe list`, `FRUit.exe restore work`.

### Почему `-u`

`pythonw.exe` без консоли буферизует `stdout` блоками, и у долгоживущего трея
лог оставался бы пустым до самого выхода. Ключ `-u` (небуферизованный вывод)
вместе с `flush=True` в логах приложения делает строки видимыми сразу.

### Почему видно два `pythonw.exe`

На Windows `.venv\Scripts\pythonw.exe` — это **стаб-редиректор** venv: он
запускает настоящий интерпретатор (например,
`...\pythoncore-3.13-64\pythonw.exe`) дочерним процессом. Поэтому в диспетчере
задач «лишний» процесс — это нормальное поведение venv, а не утечка; код
исполняется во втором процессе.

## Окружение (.venv)

Как и у mybl, утилита использует собственный `.venv`, чтобы exe работал
предсказуемо (не зависел от того, какой `python.exe` первым в PATH):

```bat
py -3 -m venv F:\FRUit\.venv
F:\FRUit\.venv\Scripts\python.exe -m pip install -r requirements.txt
```

`.venv\` в репозиторий не попадает (см. `.gitignore`).

## Иконка

```bat
python launcher\make_icon.py
```

Рисует иконку кодом (Pillow) — «стопка папок, а сверху банан»; бинарных
ассетов в репозитории нет. `build_launcher.bat` встраивает `fruit.ico` в exe,
тот же рисунок трей берёт из `fruit\icons.py`.

## Логи и данные

- `logs\fruit.log` — вывод и ошибки тихого трея (при 1 МБ ротируется в
  `fruit.log.1`).
- Пользовательские данные — в `%LOCALAPPDATA%\FRUit` (см. корневой README).
